## 1) 循环 include 的根因（“需要完整类型 vs 不需要完整类型”）

- **C/C++ 的 `#include` 是文本展开**。编译一个 `.cpp` 时，预处理器把它 `#include` 的所有 `.h` 文本粘进来，形成一个**翻译单元**（TU）再编译。
- **类的成员里如果放“对象本身”**（即 `B b;`），编译器必须立刻知道 `B` 的**完整定义**（大小、布局、析构等），否则连 `sizeof(A)` 都算不出来，**必须 `#include "B.h"`**。
- **但如果成员只是“指针/引用”**（`B* b;` / `B& b;`），此时只需要知道 **“有个类型名 B”**，不需要它的大小；**只做前向声明 `class B;` 即可**，不必 `#include "B.h"`。
> 因此：**循环 include** 通常发生在双方都把对方**作为成员对象**而不是**指针/引用**时；或者在头文件里使用了需要完整类型的操作（见下一节规则）

## 2) “不完整类型（incomplete type）”能做什么、不能做什么？

你可以只做前向声明 `class B;`，然后在 `A.h` 里写 `B* b;`。此时 **允许** 的事情：
- 声明 `B*`/`B&`/函数形参/返回值是 `B*`；
- 在类体里声明 `B` 的**指针**作为成员；
- 声明与 `B` 相关的**指针比较/赋值**等不需要知道 `B` 大小的事。
**不允许** 的事情（需要完整类型）：
- 成员里放 `B b;`（对象而不是指针/引用）；
- `sizeof(B)`、继承自 `B`、访问 `B` 的成员、调用 `B` 的非静态成员函数（除非在实现处、且那时类型已完整）；
- **`delete pB;`**：**删除指向不完整类型的指针在编译点必须是完整类型**（尤其虚析构更是必须完整）。所以通常把 `delete` 放到 `.cpp`，并 `#include "B.h"` 后再写析构，保证**编译该析构函数时 B 已完整**。
> 这点经常被忽略：**你可以在头文件里声明 `~A();`，但把定义放到 `A.cpp` 并 `#include "B.h"`，这样在 `~A()` 里做 `delete b;` 时，`B` 已经是完整类型。**

# 3) 你问的“初始化到底什么时候发生？”

分清 **编译期 vs 运行期**：
- **编译期**：编译器只是在理解语法+生成目标代码。`#include` 展开、看到类定义/函数声明/函数定义，最终把 **每个 `.cpp` 单独编译** 成 `.obj`。
- **链接期**：把各 `.obj` 合成可执行文件。此时它只关心“符号有没有定义”（比如函数体在哪个 `.obj` 里），但**不“执行”**任何初始化。
- **运行期**：程序真正跑起来的时候，才会“初始化”对象（比如 `A a;` 时才构造），**静态存储期对象**的构造则发生在 `main` 之前/之后（取决于平台/顺序规则）。
所以：
- **`#include` 头文件只是让编译器“看见声明/定义”**，保证生成的目标代码里有对函数/类型的正确引用。
- **函数体在哪个 `.cpp` 里并不影响“何时初始化对象”**，它只影响链接能不能找到那个函数体。而“初始化对象”是你的代码在运行时执行构造函数那一刻发生的。

## 什么样的情况一定不行  A包含B对象、B包含A对象
```cpp
class A
{
	B b;
};

class B
{
	A a;
}
```
这一定不行， 必须有一个是指针。

```cpp
class A
{
	B b;
};

class A;
class B
{
	A* a;
}

B.cpp
#include "classA.h"
	func()
	{
		a->Test();
	}

```
A初始化的时候，需要B，include B能得到完整的Bclass的信息。
B初始化的时候，不需要A，就能知道这个地方有个指针 Class A，然后.cpp文件中，得到了完整的A的信息，就可以进行函数访问了
