## 1) 预处理（Preprocessing）

- 处理 `#include` / `#define` / `#if` 等指令，把**头文件文本**“粘贴进来”。
- 结果是一个**纯 C++ 源文件**（称“预处理后的翻译单元”）。
- 示例：`main.cpp` 预处理后会把 `A.h`、`B.h` 展开在里面。
每个.cpp 文件单独处理一次，生成一个预处理文件。

## 2) 编译（Compilation）

- 把**每个 `.cpp` 的 C++ 源码**从文本翻译成**目标代码（机器指令的中间二进制）**。
- 产物是**目标文件**：Windows 叫 `.obj`，Linux/macOS 叫 `.o`。
- **一次只编译一个 `.cpp`**，互相**不知道**其它 `.cpp` 的函数实现在哪，只知道“有这个符号（函数/变量）存在”的**声明**就行。
- 生成obj文件， 以及对应的cpp中的<font color="#ff0000">函数机器码，以及符号表</font>

👉 分别编译四个 `.cpp`：

- **MSVC：**
    `cl /nologo /std:c++20 /EHsc /c A.cpp   // 生成 A.obj cl /nologo /std:c++20 /EHsc /c B.cpp   // 生成 B.obj cl /nologo /std:c++20 /EHsc /c main.cpp // 生成 main.obj`
- **GCC/Clang：**
    `g++ -std=c++20 -c A.cpp   -o A.o g++ -std=c++20 -c B.cpp   -o B.o g++ -std=c++20 -c main.cpp -o main.o`
    
> 注意：这个阶段，`A.cpp` 能编译成功，因为它 `#include "B.h"` 后已经“看到”了 `B::hi()` 的**声明和类定义**；`main.cpp` 能编译成功，因为它只调用了 `A::hello`，而 `A::hello` 的**定义**会在链接时解决。

先对齐术语：
### 声明（declaration）：
告诉编译器“有个名字/符号是什么类型”。   【ok】
    例：`class A;`（前向声明），`void foo(int);`（函数声明）。
### 定义（definition）**：
真正给出实体/布局/函数体。   【ok】
    例：`class A { int x; };`（类定义），`void foo(int) { ... }`（函数定义）。
### 不完整类型（incomplete type）**：
只知道“有这个类型名”，**不知道大小和布局**。  
    例：`class A;` 就是不完整类型。
### 完整类型（complete type）**：
编译器**知道大小与布局**。  
    例：`class A { int x; };`
完整类型中，函数不需要有定义，只需要有声明就ok了，
需要完整类型：  继承， 成员对象， sizeof ， new delete

# 模板的特殊性（为什么经常要求“看见实现体”）

- **模板是“用到哪种 T，就在哪个翻译单元实例化哪种 T”**。
- 因为实例化发生在**编译阶段**，所以**实例化点**必须能看到模板成员函数的**定义**（而不仅是声明），否则无法生成代码。
- 这就是为什么模板代码常写成：
    - **全部放在 `.h`**，或
    - `.h` 里 `#include "xxx.tpp"/"xxx.inl"`，把模板实现包含进来，或
    - **显式实例化**（头文件只放声明，`.cpp` 里 `template class Foo<SomeT>;` 生成固定几种 T 的实例）。

# 2) 链接器四步曲（核心流程）

### 步骤 ① 符号收集与解析（Symbol Resolution）
- 扫描所有输入（`.o/.obj`、静态库 `.a/.lib`、以及要链接的动态库的“导入库”）。
- 建一张**全局符号表**：
    - **定义**：某符号在哪个目标文件里被提供（函数体/变量本体）。
    - **引用**：哪些地方在用它（调用/取地址/访问变量）。
        
- 规则检查：
    - **未定义引用**：某符号被用到，但没有任何定义 → `undefined reference` / `unresolved external symbol`。
    - **多重定义**：同一个**强符号**在多个文件里定义 → `multiple definition`（C/ELF）或不同平台的类似报错。
    - **弱符号**（weak）/ COMDAT（MSVC）等：用于模板/内联函数等“同一实现可能出现在多个 .o” → 链接器选一个保留，其余丢弃（或折叠）。

### 步骤 ③ 重定位（Relocation Fixups）
- 之前代码里“调用 foo”的位置只是写了**占位**（如 32 位相对位移=0），链接器现在知道 `foo` 的最终地址了，就把这些占位**改写为真实（或相对）地址**。

# AI文本拷贝
## 1) `A* p = new A();` 运行时的真实流程

1. **代码位置**：`A::A()` 的机器码在 **.text**（代码段）。
    
2. **分配**：编译器在调用点把 `sizeof(A)` 作为**立即数**塞进指令（或寄存器），调用 `operator new(sizeof(A))`（也在 .text，对应运行库）。
    
    - `operator new` 从**堆**分配 `sizeof(A)` 字节，返回一块内存地址 `addr`。这块**对象存储**在**堆**，不在任何段里。
        
3. **构造**：编译器生成对 `A::A()` 的调用，把 `addr` 当作 `this`，在那块堆内存里**就地构造**：写入成员初值、如果有虚函数则写入 **vptr**（指向 A 的虚表）。
    
4. **赋值**：把 `addr` 这个指针值存入局部变量 `p`（通常在**栈**的当前栈帧里，或优化后在寄存器中）。
    

> 你可以把 `.text` 理解为“**怎么做**”的指令仓库，**对象本体不在 `.text`**，而在堆（对 `new`）/栈（对局部按值）。

---

## 2) 调用虚函数：`p->Test()`

- 典型实现（未被 devirtualize 的情况下）：
    
    1. 从对象内存（堆上的那块 `*p`）**读 vptr**；
        
    2. 以**固定偏移**在**虚表**中取出 `Test` 的函数入口地址；
        
    3. **间接跳转**到该地址，执行函数体（函数体在 **.text**）。
        
- **虚表位置**：实现相关，常在 **.rdata（Windows/PE）** 或 **.rodata（ELF）**，也就是**只读数据段**。
    
- 注意：某些情况下编译器能**去虚拟化**（已知动态类型、`final` 等），直接生成对具体实现的**直接调用**，这时不走 vtable。
## 3) 全局/静态对象的存储与初始化

用你的两个例子逐个看：

### 3.1 `A g1;`（全局，**无显式非零初值**）

- **存储位置**：对象的原始字节落在 **.bss**（零初始化区域）。
    
- **构造**：如果 `A` 的构造函数是**非平凡（non-trivial）**，程序启动时（`main` 前）运行库会通过“**初始化数组**”（ELF 的 `.init_array` / Windows 的 `.CRT$XCU` 等）**调用 `A::A()`**，把这块 `.bss` 上的内存真正构造成一个 `A`。
    
    > 也就是说：在**存储**层面在 `.bss`，但**还需要在启动阶段调用构造函数**完成**动态初始化**。
    

### 3.2 `A g2 = A{5};`（全局，**有非零初值**）

- **存储位置**：对象的原始字节落在 **.data**（已初始化静态存储）。
    
- **构造**：同样，如果 `A` 构造是非平凡的，仍会通过**启动表**在 `main` 前调用构造函数完成动态初始化（只是原始字节初值来自 .data，而不是全零的 .bss）。
    

> 口诀：**静态存储期对象的“原始字节”在 .bss（零初）或 .data（非零初）**；  
> **是否要在启动时“跑构造函数”取决于构造是否非平凡**。非平凡 → 需要跑构造；平凡 → 仅靠映射出的初值即可。

---

## 4) `static std::string s = "Test!";`（函数内静态或全局静态）

- **对象本体（`std::string`）的存储**：静态存储期 → 在 **.data** 或 **.bss**（取决于编译器如何布置原始字节，通常会放在 .data，因为需要非零状态/指针等）。
    
- **初始化**：`std::string` 必定是**非平凡**构造，需要调用其构造函数把内部指针/长度等初始化，并把 `"Test!"` 的数据拷贝或引用进去（小字符串优化时可能直接放在对象内部）。
    
    - **全局/命名空间静态**：在 `main` 前通过**全局构造**完成。
        
    - **函数内 `static`**：采用**首次进入该作用域时**的**线程安全一次性初始化**（有守卫标志），不是在 `main` 前。
        
- **字符串字面量 `"Test!"` 的存储**：在 **只读常量段**（`.rodata/.rdata`）。
    
    - `s` 的构造函数会读取该字面量的地址，初始化自身。
        

> 所以这句不能说“前面在 .bss、后面在常量区”。更准确是：**字面量在只读常量段**，**`std::string` 对象本体在静态存储（.data/.bss）**，并且**必然有构造函数调用**。
